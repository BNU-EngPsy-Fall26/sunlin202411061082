# 城市任务实验室 CITY / LAB

版本 1.3.0 · 精简试次版 · 两个经典范式的游戏化改编

## 运行

解压后直接用桌面浏览器打开 index.html，无需安装依赖。也可放在 GitHub Pages 的站点根目录，或运行 `python -m http.server 8000` 后访问 localhost:8000。正式计时使用电脑和实体键盘/鼠标，窗口至少850×580。网络字体不可用时自动回退系统字体，实验本身不依赖网络。建议所有参与者使用同样设备、浏览器缩放与窗口尺寸。

- FPS：60个正式、6个练习、3个体验；12个细分组合各5次。
- 导航：72个正式、6个练习、3个体验；12个细分组合各6次，左/直/右各2次。

## 实验1：射击搜索

2搜索类型（特征/联合）×3项目总数（8/16/24）×2提示（中性/可靠半区）×5重复=60。
目标固定为橙色圆形；特征条件干扰项为蓝色圆形；联合条件为蓝色圆形和橙色方形。每轮总有且仅有一个目标。中央点击后先显示500ms提示，随后呈现静态靶子。第一次左键pointerdown完成本轮，点击空白也算错。8秒超时。每15轮休息。
目标位置在对应条件间匹配、左右项目数相等、项目不重叠。RT包含搜索/决策/鼠标移动，不是纯搜索时间。可靠提示全部有效，结论不能推广到不可靠提示。

## 实验2：配送导航

3地图模式（北向上/航向上/北向上+局部方向参照）×4实际朝向×6重复=72。每个组合左/直/右各2次。每种模式24次，模式顺序按编号哈希在6种排列中分配。研究者应检查少量样本是否均衡。练习6轮，体验3轮。
骑手位于路口，绿色路线显示下一步。以骑手视角按←/↑/→作答。10秒超时。每12次休息；每种地图经过12次后显示一次施工/路线更新通知，通知不计时。此通知不是独立实验操纵。
程序使用独立但连续呈现的配送路口片段，不是自由驾驶模拟器、连续真实城市寻路或订单记忆实验。每轮准备后才呈现路线。错误后回到预设试次序列，不增加路线难度。不测认知地图学习，不可据此声称某地图总体更优。不同模式使用场景变体，实际朝向和转向严格平衡。

## 计时与中断

requestAnimationFrame回调中呈现刺激并以performance.now()开始计时；首次有效输入结束。本程序不声称有经过硬件测量的绝对显示时延精度。准备、提示、休息、反馈不计入RT。窗口失焦、切换或缩放会标记当前试次无效，当前条件移至后续补做；原记录保留。快速体验的响应上限为60秒，仅方便试玩，绝不进入正式分析。

## 收数前

1. 阅读 DESIGN-PREDICTIONS.md 并由本人修改、确认预测与设计决策。
2. 请1—2名他人预试检查操作、时限与时长；修改后冻结版本，不把旧预试直接并入正式样本。
3. 在课程GitHub仓库收数前commit预测。这里自动生成的代码提交不等于你已完成预注册。
4. “研究设置”中确认准备；可填写自己的6位课程项目码。不要填写下载密钥。
5. 点击生成被试链接，可将 study=1 与项目码带给新浏览器，免去被试做研究者确认。该参数不是访问控制，也不改变站点分享权限。
6. 研究者交替安排两个实验先后；同一人用同一匿名编号完成两项。至少5名他人，不以显著性决定是否继续招募。

## 数据与上传

逐试次保存到当前浏览器localStorage。清理浏览器可能丢失，及时导出。退出任务保留未完成记录，当前不支持续做未完成会话。导出CSV包括练习/中断/错误/超时，必须按字段过滤。JSON保存会话元数据。数据页面支持导入本项目导出的CSV或JSON，导入仅留在当前页面内存，不会自动上传。支持多选和分批追加，自动按会话去重；刷新前可导出合并JSON。

上传接口按课程截图示例：POST https://attention-lab-production.up.railway.app/api/hw2/submit，body包括project、experiment、participant、condition、trials；trials增加cond字段。只允许手动上传完整非体验记录，上传前确认。射击实验名visual_search_cue；导航map_orientation_aid。接口尚未用研究者自己的真实项目联调，不能将本地完成误报为课程后台已收数。若接口失败，保留CSV并检查课程平台最新文档。不要复用参考同学的项目码。

## 分析

- 每编号×实验只保留最后一个完成且条件齐全的会话；体验、未完成会话不纳入。
- 原始无效中断试次不纳入分母；有效正式试次中错误和超时记为错误。
- RT只使用正式、未中断、正确、未超时且RT≥150ms记录。
- 每被试每条件算中位RT，再算被试间均值；正确率同样以被试为单位。
- 搜索曲线只用中性提示试次，比较项目数增加的变化。其他表格保留全部条件。
- v1.3.0配对收益：先求每个细分条件的中位RT，相关条件等权平均，再求同一人的A−B；缺少任一必要条件RT则不进入该比较。d_z为差值均值/差值样本标准差，少于2人或标准差为0时不计算。
- 小样本强调方向、量级、正确率及个体差异。页面不生成假数据、不预写显著性结论。收集后须由研究者补充与原论文比较及讨论。

## 1.1.1 颜色修复

修复基础target类与目标颜色类重名造成的CSS覆盖。目标使用独立orangeCircle类；蓝色圆形保持blueCircle类，橙色方形保持orangeSquare类。已知受影响的1.0.0/1.1.0射击记录继续保留、可导出，但不纳入分析或上传；导航记录不受此颜色问题影响。收集过旧版射击数据时，应重新完成修复后的射击任务，不能将旧记录当作有效实验数据。

## v1.3.0 完整分析看板

五个页签：总览、射击、导航、数据质量、原始记录。射击提供4条搜索曲线、个体OLS斜率、提示收益差值之差；导航提供4种朝向×3地图曲线、总体及各朝向配对比较。两项都展示正确率、个人配对图、平均差、95% t置信区间和配对dz。绘图错误线为被试间均值区间，不是试次SD。

95% t区间以被试为单位，df≤30使用临界值表，df>30使用展开近似；n<2不估计区间。区间依赖相应分布假设，小样本不能可靠验证。正确率区间不截断，可能越过0—100%，仅作谨慎描述。新增比较未计算p值或多重校正，均作为探索性结果，不能事后称为预注册。

新增汇总CSV、个人条件及差值CSV、真实结果描述Markdown导出；没有数据时不生成结论。质量页列出中断、错误、超时、过快正确、可分析RT、空条件、任务顺序、排除原因。正式记录筛选验证12个准确条件键和细分计数，保留最后一次完整会话；不会删除原始数据。

运行 `node tests/test-stats.cjs` 核对已知数值、斜率、配对CI及筛选；运行 `node tests/test-analysis-ui.cjs` 检查分析页面生成、合并导入和导出逻辑。测试数据仅在Node内存，绝不保存成真实研究数据。
